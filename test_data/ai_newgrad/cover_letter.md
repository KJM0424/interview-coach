# 자기소개서 [가상 인물 - 테스트용]

## 1. 지원 동기와 입사 후 포부 (700자)
부트캠프 최종 프로젝트로 회사 내규 검색 챗봇을 만들면서, 같은 질문에도 근거 문서를 엉뚱하게 가져오는 답변이 많다는 걸 알게 됐습니다. 처음에는 프롬프트만 계속 고쳤지만 나아지지 않았고, 질문 120개와 정답 근거 문단으로 평가 세트를 만들어 검색 단계부터 쟀습니다. 문단을 조항 단위로 다시 자르고 조항 번호를 메타데이터로 붙인 뒤 정답 근거 포함률이 0.48에서 0.74로 올랐습니다.
한빛AX의 "근거로 말하는 사람"이라는 인재상을 보고, 제가 프로젝트에서 가장 오래 붙잡았던 문제를 실제 고객사 문서로 풀 수 있는 곳이라고 생각했습니다. 입사 후에는 고객사 문서 특성에 맞는 평가 세트부터 만드는 엔지니어가 되고 싶습니다.

## 2. 협업 경험 (600자)
최종 프로젝트에서 팀장을 맡았을 때, 화면 담당 팀원과 검색 담당 팀원이 일정 문제로 부딪혔습니다. 화면 쪽은 데모를 위해 빨리 API가 필요했고, 검색 쪽은 성능을 먼저 올리고 싶어 했습니다. 저는 고정된 가짜 응답을 주는 API를 먼저 만들어 화면 작업이 멈추지 않게 하고, 검색 개선은 평가 세트 점수로 진척을 공유하자고 제안했습니다. 매일 아침 10분 동안 점수와 남은 작업을 공유했고, 마감 이틀 전에 실제 API로 교체했습니다.

## 3. 실패 경험 (600자)
회의록 요약 서비스에서 전사 결과를 그대로 요약에 넣었다가, 쉬는 시간 구간에서 같은 문장이 수십 번 반복되는 전사 오류 때문에 요약이 엉망이 된 적이 있습니다. 데모 당일 발견해서 급하게 반복 문장을 지우는 규칙만 넣고 넘어갔습니다. 이후 원인을 찾아보니 조용한 구간에서 이전 문장을 이어 쓰는 설정 때문이었고, 설정을 끄고 반복 제거를 후처리 단계로 정리했습니다. 이 일로 결과물만 보지 말고 중간 단계 출력을 먼저 확인하는 습관이 생겼습니다.

## 4. 군 경험 (400자)
포병 부대에서 사격지휘(FDC)를 맡아 관측 정보로 사격 제원을 계산했습니다. 계산 실수가 바로 안전 문제로 이어지기 때문에, 두 명이 따로 계산하고 결과를 대조하는 절차를 지켰습니다. 이 경험이 AI 결과를 한 번 더 다른 방법으로 확인하는 습관의 바탕이 됐습니다.
