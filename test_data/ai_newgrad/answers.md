# 정민호 세트 테스트용 답변 스크립트

## 자료에 있는 사실 / 없는 사실 (함정)
| 자료에 있음 | 자료에 없음 (함정) |
|---|---|
| 내규 PDF 86개, 질문 120개 평가 세트 | 리랭커, 하이브리드 검색(BM25) |
| Top-3 포함률 0.48 → 0.74 (조항 단위 청킹 + 메타데이터) | 응답 시간 개선 (오히려 못 함, 평균 4초) |
| 팀장, 가짜 응답 API로 일정 갈등 해결 | 실제 기업 고객 대상 운영 경험 |
| Whisper 반복 전사 오류 → 설정 끄고 후처리 | 쿠버네티스, 대규모 트래픽 |
| FDC 이중 계산 대조 | 정보처리기사 최종 합격 (실기 준비 중) |
| 표 PDF 처리는 해결 못 함 | 지어낸 답변 비율 수치 |

## A. 강한 답변 - RAG 성능 개선
> 처음에는 답변이 이상하면 프롬프트를 고쳤는데 5번을 고쳐도 나아졌는지 알 수가 없었습니다. 그래서 팀원들과 질문 120개를 만들고, 질문마다 정답 근거 조항을 표시해 평가 세트를 만들었습니다. 정답 조항이 검색 결과 상위 3개 안에 들어오는지를 기준으로 재보니 0.48이었고, 원인을 보니 500자 고정 길이로 자르면서 조항 중간이 잘리고 있었습니다. 조항 단위로 다시 자르고 조항 번호와 문서명을 메타데이터로 붙인 뒤 0.74까지 올렸습니다. 다만 표가 들어간 PDF는 해결하지 못해서 한계로 발표했습니다.

## B. 강한 답변 - 협업/갈등
> 화면 담당은 데모 준비 때문에 API가 빨리 필요했고, 검색 담당은 성능부터 올리고 싶어 해서 일정이 부딪혔습니다. 저는 고정된 응답을 돌려주는 가짜 API를 먼저 만들어 화면 작업이 멈추지 않게 했고, 검색 쪽은 평가 세트 점수로 진척을 공유하자고 했습니다. 매일 아침 10분씩 점수와 남은 작업을 공유했고 마감 이틀 전에 실제 API로 바꿨습니다.

## C. 강한 답변 - 지원 동기
> 프로젝트에서 가장 오래 붙잡은 문제가 "좋아진 걸 어떻게 증명하느냐"였습니다. 한빛AX 인재상에 "근거로 말하는 사람"이 있고, 금융 약관이나 내부 규정 RAG처럼 제가 해본 문서 검색 문제를 실제 고객사 규모로 다루는 곳이라 지원했습니다. 아직 실제 고객사 운영 경험은 없어서, 입사 초반에는 고객사 문서별 평가 세트를 만드는 일부터 맡고 싶습니다.

## D. 약한 답변
> 팀원들과 열심히 협력해서 챗봇 성능을 많이 개선했습니다. 앞으로도 꾸준히 성장하겠습니다.

## E. 지어낸 경험 (감점돼야 함)
> 하이브리드 검색과 cross-encoder 리랭커를 붙여서 정확도를 95%까지 올렸고, 응답 시간도 4초에서 0.8초로 줄였습니다. 실제 고객사 3곳에 배포해 하루 1만 건 질문을 처리했습니다.

## F. 자격증 과장 (감점돼야 함)
> 정보처리기사를 취득해서 소프트웨어 공학 기초도 탄탄합니다.
