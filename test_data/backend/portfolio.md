# 이도윤 포트폴리오 (테스트용 가상 인물)

## 1. 추천 API 응답 속도 개선 (2024.03 ~ 2024.05)

### 문제
- 상품 상세 페이지의 추천 API p95 응답 시간이 820ms까지 올라갔다.
- 같은 기간 상품 상세 페이지 이탈률이 4.1%p 늘었다.

### 원인 찾기
1. APM(Datadog)에서 구간별 지연을 보니 DB 구간이 전체의 78%였다.
2. PostgreSQL slow query 로그에서 상품마다 쿼리를 따로 보내는 N+1 패턴을 찾았다. 요청 1건에 쿼리가 평균 41번 나갔다.

### 해결
- ORM 조회를 상품 ID 목록으로 한 번에 가져오는 배치 조회로 바꿨다. 요청당 쿼리 41회 → 3회.
- 추천 결과 캐시(Redis)도 검토했지만, 재고·가격이 5분 단위로 바뀌어 정합성 문제가 커서 적용하지 않았다.

### 검증
- 운영 트래픽 1시간 분량을 Locust로 재생해 배포 전후를 같은 조건에서 비교했다.
- p95 820ms → 210ms, 이탈률은 배포 4주 뒤 원래 수준으로 돌아왔다.

### 내 역할
- 원인 분석, 쿼리 수정, 부하 테스트를 혼자 맡았다. 코드 리뷰는 팀 시니어 1명이 했다.

## 2. 정산 배치 시간 단축 (2024.08 ~ 2024.10)

- 매일 새벽 가맹점 정산 배치가 4시간 걸려 오전 업무 시작 전에 끝나지 않는 날이 생겼다.
- 가맹점을 1,000곳 단위 청크로 나눠 병렬 처리하고, 실패한 청크만 재시도하도록 바꿨다.
- 배치 시간 4시간 → 40분. 실패 시 전체 재실행이 필요 없어졌다.
- 정산 담당 기획자와 "부분 실패 시 어떤 가맹점부터 다시 돌릴지" 기준을 함께 정했다.

## 3. 결제 웹훅 중복 처리 장애 (2025.01)

- PG사 웹훅이 재전송될 때 같은 결제를 두 번 처리해 포인트가 이중 적립된 사례가 23건 나왔다.
- 결제 ID + 이벤트 타입으로 멱등키를 만들어 이미 처리한 웹훅은 무시하도록 바꿨다.
- 이중 적립된 23건은 CS팀과 함께 회수·안내했다.
- 이후 6개월 동안 같은 유형의 장애는 0건이다.
- 장애 회고 문서를 작성해 팀 위키에 공유했다.
