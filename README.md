# AI 면접 코치

지원 직군, 회사 정보, 내 자료(자소서·이력서·포트폴리오)를 넣으면 LLM(기본 Gemini, 선택 Claude)이 맞춤 질문을 하나씩 던지고, 평가위원 4명이 답변을 채점하는 모의 면접 앱이다.

## 기능

- 첫 화면에서 직군(AI 엔지니어 / 백엔드 개발자 / 직접 입력), 회사 정보, 자료 파일(txt, md, pdf, docx), 질문 개수(5 / 10)를 정하고 면접을 시작한다. 처음 요구사항은 사이드바였지만 웹사이트형 화면으로 바꾸면서 본문으로 옮겼다.
- 상단의 "새 면접"으로 설정 화면에 돌아갈 수 있고, 이전에 입력한 직군, 회사 정보, 자료가 기본값으로 남는다.
- 답변은 글로 쓰거나, 입력창의 마이크 버튼을 눌러 말로 채울 수 있다. 브라우저 내장 음성 인식(Web Speech API)을 써서 API 비용이 없다. 받아쓴 글은 보내기 전에 고칠 수 있다.
  - Chrome, Edge, Safari에서 동작하고 Firefox는 지원하지 않는다.
  - Chrome은 음성을 Google 서버에서 글자로 바꾼다. 음성이 외부로 나가는 게 싫으면 글로 입력한다.
  - 마이크는 `localhost`나 `https` 주소에서만 쓸 수 있다. 같은 와이파이의 다른 기기에서 `http://192.168...`로 접속하면 동작하지 않는다.
- 질문은 미리 정한 목록 없이 매번 API가 입력 맥락과 이전 질문을 보고 1개씩 만든다.
- 답변마다 평가위원 4명이 각자 10점 만점 점수, 이유 1줄, 개선 포인트 1줄을 준다.
  - 기술 면접관(직무 역량), 인사 면접관(인성·조직 적합도), 실무 팀장(협업·문제 해결), 임원(회사 이해도·성장성)
- 평균 7점 미만이면 부족한 점을 알려주고 같은 질문에 다시 답하게 한다. 재답변은 질문당 최대 2회이고, 그래도 7점 미만이면 다음 질문으로 넘어간다.
- 평균 7점 이상이면 답변을 파고드는 꼬리 질문 1개를 하고 다음 질문으로 넘어간다. 꼬리 질문 답변도 평가하지만 재답변은 없다.
- 면접이 끝나면 질문별 점수표, 평가위원별 평균, 강점 3개, 보완할 점 3개, 모범 답변 예시 1개를 담은 리포트를 보여주고 `.md`로 내려받게 한다.

## 실행 방법

Python 3.11 이상이 필요하다. streamlit 1.66은 3.11 이상, anthropic 2.3은 3.10 이상을 요구한다. google-genai는 2.33에서 확인했다. 개발 환경은 Python 3.12다.

`style.css`가 Streamlit 내부 DOM 구조(`data-testid`)에 기대고 있어서 streamlit은 검증한 1.66.1로 고정했다. 버전을 올리면 화면을 다시 확인해야 한다.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 어떤 LLM을 쓸지 정하기

| `LLM_PROVIDER` | 모델 | 필요한 키 | 비용 |
|---|---|---|---|
| `gemini` (기본) | `gemini-3.8-flash` | `GEMINI_API_KEY` ([Google AI Studio](https://aistudio.google.com)에서 발급) | 무료 등급 사용 가능. 사용량 한도가 있다 |
| `anthropic` | `claude-haiku-5-5` | `ANTHROPIC_API_KEY` | 유료. 5문항 면접 1회 약 $0.03로 추정 (측정값 아님) |

**Gemini 무료 등급에는 개인 정보를 넣지 않는다.** [Gemini API 약관](https://ai.google.dev/gemini-api/terms)에 따르면 무료 등급에서는 입력과 응답이 Google 서비스 개선에 쓰이고 사람 검토자가 읽을 수 있으며, 약관이 민감 정보나 개인 정보를 넣지 말라고 명시한다. 그래서 Gemini를 쓰는 동안 앱 화면에 이 안내가 뜬다. 실제 이력서로 연습하려면 `LLM_PROVIDER=anthropic`으로 바꾸거나 Gemini 유료 등급을 쓴다.

### 키 넣기

앱은 `st.secrets`를 먼저 읽고, 없으면 `.env`를 읽는다. 둘 중 한 곳에 둔다.

```bash
# .env (.env.example을 복사해서 사용)
LLM_PROVIDER=gemini
GEMINI_API_KEY=...
# Claude를 쓸 때
# LLM_PROVIDER=anthropic
# ANTHROPIC_API_KEY=sk-ant-...
```

```toml
# .streamlit/secrets.toml
LLM_PROVIDER = "gemini"
GEMINI_API_KEY = "..."
```

두 파일 모두 `.gitignore`에 들어 있다.

```bash
streamlit run app.py
```

## 화면 설계

토스 채용 페이지의 디자인 언어를 참고했다. 흰 바탕, 상단 내비게이션, 연한 파란 그라데이션 히어로, 굵은 헤드라인, 회색 단계와 파란 강조색 하나로 구성한다. 토스 로고, 이름, 전용 글꼴은 쓰지 않았다.

- 구현: 입력은 Streamlit 위젯, 표시 전용 요소(질문, 평가 카드, 결과 화면)는 `st.html`로 그린 HTML이다. 스타일은 `style.css`에 모았다. Streamlit 기본 헤더와 사이드바는 숨긴다.
- 보안: 사용자 답변과 모델 응답은 HTML에 넣기 전에 모두 이스케이프한다. 스크립트 실행은 저장소에 있는 `voice_input.js` 한 파일에만 허용하고, 나머지 `st.html`은 `<script>`를 실행하지 않는다.
- 글꼴: Pretendard를 CDN에서 불러온다. 불러오지 못하면 sans-serif로 대체하도록 설정했다 (오프라인 동작은 확인하지 않았다).
- 색: 작은 글자는 흰 바탕 대비 4.5:1 이상인 색만 쓴다. 토스 웹에서 쓰는 파란색(#3182F6)은 대비가 3.7:1이라 막대와 큰 버튼에만 쓰고, 파란 글자는 #1B64DA(5.4:1)를 쓴다. 통과/미달은 색과 함께 "기준 통과", "기준 미달" 글자로도 표시한다.
- 라이트 테마만 지원한다.
- 화면 구성
  - 정보 입력: 히어로 + 왼쪽 입력 폼 + 오른쪽 안내 카드
  - 면접: 질문 번호와 진행 막대, 질문은 큰 글씨, 내 답변은 오른쪽 말풍선, 평가는 평가위원별 점수 막대가 있는 카드
  - 결과: 평균 점수 히어로, 평가위원별 점수 카드, 질문별 점수 목록, 강점·보완할 점, 원래 답변과 다시 쓴 답변 비교
- 폭 720px 이하에서는 2단 배치를 1단으로 바꾸고 글자 크기를 줄인다.

## AI를 어디에 어떻게 썼고, 어떻게 검증했는지

### 앱 안에서 AI를 쓰는 곳

모든 호출은 LLM API 한 번짜리 요청이다(기본 Gemini `gemini-3.8-flash`, 선택 Claude `claude-haiku-5-5`). 대화 기록을 API에 넘기지 않고, 필요한 맥락을 매번 프롬프트에 태그로 넣는다. 어느 API를 쓰든 같은 프롬프트(`prompts.py`)와 같은 검증 코드를 쓴다.

| 단계 | 프롬프트 | 응답 형식 | 앱이 하는 검증 |
|---|---|---|---|
| 질문 생성 | `QUESTION_SYSTEM` | 질문 문장 | 이전 질문 목록을 넣어 중복을 줄이고, 앞뒤 따옴표를 제거 |
| 꼬리 질문 | `FOLLOWUP_SYSTEM` | 질문 문장 | 답변에 나온 내용만 전제하도록 제약 |
| 답변 평가 | `EVALUATION_SYSTEM` | JSON | 아래 참고 |
| 최종 리포트 | `REPORT_SYSTEM` | JSON | 강점·보완점 각 3개 이상, 모범 답변 비어 있지 않은지 확인 |

평가 결과를 믿을 수 있게 하려고 정한 원칙은 다음과 같다.

- 평가 시스템 프롬프트에 "자료에 없는 경험을 지어내 칭찬하지 말 것"을 넣고, 점수 근거를 답변에 실제로 있는 내용으로 한정했다. 지원자 자료는 답변과 맞는지 확인하는 용도로만 쓰게 했다.
- 점수 구간별 기준(9~10, 7~8, 5~6, 3~4, 0~2)을 프롬프트에 적어 평가위원 간 기준을 맞췄다.
- JSON을 받는 호출(평가, 리포트)은 JSON 모드로 보낸다. Gemini는 `response_mime_type="application/json"`으로 JSON만 돌려주게 한다. 그래도 앱에서 다시 파싱하고 검증한다. 평가위원 4명이 이름 그대로 모두 있는지, 점수가 0~10 숫자인지, 이유와 개선 포인트가 비어 있지 않은지 본다. 파싱이나 검증이 실패하면 1번 재시도하고, 그래도 실패하면 에러를 보여준다.
- 평균 점수, 재답변 여부, 평가위원별 평균, 모범 답변 대상(가장 낮은 점수의 답변)은 모델이 아니라 코드가 계산한다. 합격선 판단이 모델의 산수에 의존하지 않게 하기 위해서다.
- 모범 답변은 자료와 답변에 있는 사실만 쓰고, 없는 수치는 `[본인 사례의 구체적 수치]` 같은 자리표시자로 남기게 했다.
- 응답이 최대 길이에서 잘리면 파싱 실패로 보고 재시도한다. Claude의 거절(`refusal`)이나 Gemini 안전 필터 차단은 다시 보내도 같을 가능성이 커서 재시도하지 않고 안내한다. 두 모델 모두 생각(thinking) 내용은 빼고 최종 답 텍스트만 읽는다.
- 429(사용량 초과), 5xx, 연결 오류는 SDK가 자동으로 2번 더 시도한다. 그래도 실패하면 이유별 안내(키 오류, 한도 초과, 연결 실패)를 보여 준다.
- API 호출이 실패하면 세션 상태를 바꾸지 않는다. 필요한 호출을 모두 끝낸 뒤에 상태를 바꾸기 때문에, 실패한 답변은 "같은 답변으로 다시 시도" 버튼으로 다시 보낼 수 있다.

### 개발에 AI를 쓴 곳

요구사항(기능, 제약, 산출물 목록)은 사람이 작성했고, 코드와 이 README 초안은 Claude Code(Claude Opus 5.5)가 작성했다. 처음 요구사항의 모델은 `claude-haiku-5-5`였지만, API 비용을 줄이기 위해 사람의 요청으로 Gemini를 기본으로 바꾸고 Claude는 선택지로 남겼다. 화면은 "AI가 만든 느낌이 나지 않게", "토스 웹사이트처럼"이라는 요청을 받아 Claude Code가 토스 채용 페이지를 캡처해 참고하며 다시 설계했다.

### 어떻게 검증했는지

자동 테스트와 수동 테스트 방법은 [TESTING.md](TESTING.md)에 정리했다. 아래는 개발 중에 실제 API 키 없이 확인한 항목이다.

- `pytest` 70개 통과, `ruff format`, `ruff check` 통과. 화면 흐름 테스트는 가짜 LLM 클라이언트를 쓴다. Gemini·Claude 클라이언트 테스트는 SDK 응답 객체(생각 내용이 섞인 응답 포함)와 SDK 예외를 직접 만들어 넣는다. 확인한 내용:
  - 5점 답변 3번 → 재답변 안내 1/2, 2/2 → 다음 질문으로 이동
  - 8점 답변 → 꼬리 질문 → 꼬리 답변 평가 → 다음 질문
  - JSON 파싱 1회 실패, 응답 잘림 → 1번 재시도로 정상 진행. 2회 연속 실패 → 에러 표시, 상태 변화 없음, "다시 시도"로 이어서 진행
  - 모델 거절과 안전 필터 차단은 재시도하지 않음
  - Gemini: 모델 ID, 시스템 프롬프트, JSON 모드 전달, 생각 내용 제외, 잘못된 키(400·403)·한도 초과(429)·서버 오류·연결 오류를 앱용 오류로 바꿈
  - `LLM_PROVIDER`별 키 이름, 알 수 없는 값 안내, Gemini일 때만 개인 정보 안내 표시
  - 기본 공급자를 Claude로 바꾸거나 JSON 모드를 빼면 테스트가 실패하는 것도 확인한 뒤 되돌렸다
  - 결과 화면의 평가위원별 평균(손으로 계산한 7.7과 일치), 모범 답변 대상(최저점 Q1), 내려받는 .md 표
  - 답변과 모델 응답 속 `<script>`, `<img onerror>`가 이스케이프됨
  - 키 로딩 순서(`st.secrets` 우선, 없으면 `.env`), 새 면접 시 이전 입력 유지
  - 테스트가 실제로 잡아내는지 보려고 합격 기준을 9점으로 바꿔 돌렸고, 3개가 실패하는 것을 확인한 뒤 되돌렸다
- 파일 파싱: `test_data/`의 텍스트 PDF, 표가 있는 docx, cp949 txt, 스캔 이미지 PDF, 깨진 PDF, 빈 파일로 확인했다. 이 과정에서 브라우저로 만든 PDF는 띄어쓰기가 제어 문자(`\x01`)로 추출되는 문제를 찾아, 추출한 글자의 제어 문자를 공백으로 바꾸게 고쳤다.
- 화면: 가짜 클라이언트로 정보 입력·면접 중·결과 상태를 만든 뒤 Chrome으로 1280px·390px 폭에서 캡처해 확인했다. 두 폭 모두 가로 스크롤이 생기지 않는다. 캡처로 찾아 고친 문제는 다음과 같다.
  - Streamlit이 `st.html` 안의 목록에 기본 들여쓰기(32px)를 넣던 문제
  - 상단 바와 히어로 사이에 16px 흰 틈이 생기던 문제
  - 숨긴 아바타 자리만큼 여백이 남아 내 답변 말풍선이 오른쪽에 붙지 않던 문제
- 음성 입력: 헤드리스 Chrome에서 브라우저 음성 인식 객체를 가짜로 바꿔 확인했다. 마이크 버튼 위치, 받아쓴 글이 기존 글 뒤에 이어 붙는지, 보내면 받아쓰기가 멈추고 늦게 온 인식 결과가 입력창을 다시 채우지 않는지, 마이크 권한 거부와 미지원 브라우저 안내, 390px 폭 표시를 봤다. 이 과정에서 `st.html`이 스크립트 안에 `<svg` 같은 태그 모양 문자열이 있으면 스크립트를 아예 실행하지 않는 것을 찾아, 아이콘을 DOM API로 만들게 바꾸고 회귀 테스트를 넣었다.
