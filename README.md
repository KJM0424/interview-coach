# AI 면접 코치

내 자료(자소서·이력서·포트폴리오)와 지원 회사 정보를 넣으면, LLM이 맞춤 질문을 하나씩 던지고 평가위원 4명이 답변마다 채점하는 Streamlit 모의 면접 앱.

## 주요 기능

- **맞춤 질문**: 미리 정한 목록 없이 내 자료와 회사 정보를 보고 질문을 하나씩 만든다.
- **평가위원 4명 채점**: 기술 면접관, 인사 면접관, 실무 팀장, 임원이 각자 10점 만점 점수, 이유 1줄, 개선점 1줄을 준다.
- **재답변과 꼬리 질문**: 평균 6점 미만이면 같은 질문에 최대 2번 다시 답하고, 6점 이상이면 답변을 파고드는 꼬리 질문이 이어진다.
- **결과 리포트**: 질문별 점수, 평가위원별 평균, 강점·보완할 점 각 3개, 다시 쓴 모범 답변. `.md`로 내려받을 수 있다.
- **음성 답변**: 입력창의 마이크 버튼으로 말하면 답변 칸이 채워진다. 브라우저 내장 음성 인식이라 비용이 없다.

## 빠른 시작

Python 3.11 이상이 필요하다.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # GEMINI_API_KEY 입력
streamlit run app.py
```

키는 `.streamlit/secrets.toml`에 넣어도 된다. 앱은 `st.secrets`를 먼저 읽고, 없으면 `.env`를 읽는다. 두 파일 모두 git에서 제외된다.

## LLM 선택

`.env`의 `LLM_PROVIDER`로 고른다.

| `LLM_PROVIDER` | 모델 | 필요한 키 | 비용 |
|---|---|---|---|
| `gemini` (기본) | `gemini-3.8-flash` | `GEMINI_API_KEY` ([Google AI Studio](https://aistudio.google.com)) | 무료 등급 사용 가능 |
| `anthropic` | `claude-haiku-5-5` | `ANTHROPIC_API_KEY` | 유료. 5문항 1회 약 $0.03 (추정) |

> **Gemini 무료 등급에는 실제 개인 정보를 넣지 않는다.**
> [약관](https://ai.google.dev/gemini-api/terms)상 무료 등급의 입력과 응답은 Google 서비스 개선에 쓰이고 사람이 읽을 수 있다. 앱도 Gemini 사용 중에는 이 안내를 띄운다. 연습은 `test_data/`의 가상 자료로 하고, 실제 이력서는 Claude나 Gemini 유료 등급으로 쓴다.

## 평가 방식

```
답변 제출
  → LLM 1회 호출로 평가위원 4명 점수·이유·개선점을 JSON으로 받음
  → 코드가 JSON 검증 (실패하면 1번 재시도)
  → 코드가 평균 계산 = 4명 점수의 평균
  → 다음 단계 결정
```

| 상황 | 다음 단계 |
|---|---|
| 본 질문, 평균 6.0 이상 | 꼬리 질문 1개 |
| 본 질문, 평균 6.0 미만, 재답변 기회 남음 | 부족한 점 안내 후 같은 질문 재답변 (최대 2번) |
| 본 질문, 평균 6.0 미만, 재답변 2번 다 씀 | 다음 본 질문 |
| 꼬리 질문 | 한 번 평가하고 다음 본 질문 |

합격선은 `app.py`의 `PASS_SCORE`(기본 6.0)로 바꾼다.

리포트의 점수는 본 질문의 **마지막 답변**과 답한 꼬리 질문으로 계산하고, 평균이 가장 낮은 답변을 모범 답변으로 다시 쓴다.

## 프로젝트 구조

```
app.py              화면, 면접 진행 상태, 파일 파싱, 응답 검증, 리포트
llm_client.py       Gemini·Claude API 호출과 오류 처리
prompts.py          질문·꼬리 질문·평가·리포트 프롬프트 (역할 / 입력 / 제약 / 출력 구조)
style.css           화면 스타일 (토스 채용 페이지의 디자인 언어 참고)
voice_input.js      마이크 버튼 (브라우저 음성 인식)
tests/              자동 테스트 (실제 API를 부르지 않음)
test_data/          가상 지원자 자료, 가상 회사 공고, 예외 파일
TESTING.md          테스트 방법과 수동 테스트 시나리오
```

## AI를 어디에 어떻게 썼고, 어떻게 검증했는지

### 앱 안에서

| 단계 | AI가 하는 일 | 코드가 하는 확인 |
|---|---|---|
| 질문 생성 | 자료와 회사 정보를 보고 질문 1개 작성 | 이전 질문 목록을 넣어 중복 방지 |
| 답변 평가 | 평가위원 4명의 점수·이유·개선점 (JSON) | 4명 모두 있는지, 점수 0~10인지, 빈 칸 없는지 검증. 실패하면 1번 재시도 |
| 꼬리 질문 | 답변 속 주장 하나를 골라 근거를 묻는 질문 작성 | - |
| 리포트 | 강점·보완점 각 3개, 모범 답변 (JSON) | 개수와 빈 칸 검증. 실패하면 1번 재시도 |

결과를 믿을 수 있게 하려고 정한 원칙은 다음과 같다.

- 평가 프롬프트에 "**자료에 없는 경험을 지어내 칭찬하지 말 것**"을 넣고, 점수 근거를 답변에 실제로 있는 내용으로 제한했다.
- 평균, 합격선(6점) 판정, 평가위원별 평균, 모범 답변 대상은 **모델이 아니라 코드가 계산**한다.
- 모범 답변은 자료에 없는 수치를 지어내지 않고 `[본인 사례의 구체적 수치]` 같은 빈칸으로 남긴다.
- 사용자 답변과 모델 응답은 화면에 넣기 전에 HTML 이스케이프한다.

### 개발 과정에서

요구사항은 사람이 작성했고, 코드와 문서는 Claude Code(Claude Opus 5.5)가 작성했다. 화면 디자인, Gemini 전환, 음성 입력은 사람의 요청에 따라 Claude Code가 추가하거나 다시 만들었다.

### 검증

- **자동 테스트 70개**: 가짜 LLM 클라이언트로 면접 전체 흐름, 재답변·꼬리 질문 규칙, JSON 실패 재시도, API 오류 처리, 파일 파싱, HTML 이스케이프를 확인한다.
- **화면**: Chrome에서 PC(1280px)와 모바일(390px) 화면을 캡처해 확인했다.
- **검증 중 찾아 고친 문제**: 브라우저에서 만든 PDF는 띄어쓰기가 제어 문자로 추출되던 문제, Streamlit이 특정 스크립트를 실행하지 않던 문제, 화면 여백 문제 3건.
- **아직 확인하지 못한 것**: 실제 Gemini·Claude 호출 결과(질문 품질, 평가 타당성), 실제 마이크 음성 인식, Safari·Firefox 표시.

테스트 실행법과 수동 테스트 시나리오는 [TESTING.md](TESTING.md)에 있다.

```bash
pip install -r requirements-dev.txt
pytest
```

## 참고

- streamlit은 `1.66.1`로 고정했다. `style.css`가 Streamlit 내부 구조에 기대고 있어서, 버전을 올리면 화면을 다시 확인해야 한다.
- 음성 입력은 Chrome·Edge·Safari에서 동작하고 Firefox는 지원하지 않는다. Chrome은 음성을 Google 서버에서 글자로 바꾼다. 마이크는 `localhost`나 `https` 주소에서만 쓸 수 있다.
- 라이트 테마만 지원한다.
